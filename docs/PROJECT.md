# Устройство проекта

## Назначение

PoseSketch помогает начинающему художнику поставить упрощённую пространственную фигуру, выбрать ракурс и рисовать с неё. Это статические позы: без анимации и временной шкалы. Ориентир — тонкие тёмные линии, овальная голова, красные суставы, простые направленные кисти и стопы.

## Архитектура

- `src/model.ts`: отдельные параметры пропорций, формат Pose версии 1, пресеты, преобразования и аналитическая двухсегментная IK. Длины сегментов постоянны. Pole angle определяет плоскость сгиба, включая вырожденные направления. Ограничения сгиба работают через минимальную и максимальную досягаемость; вращения ограничиваются по частям тела.
- `src/scene.ts`: Three.js, объёмные геометрические элементы и тонкие цилиндры скелета, глубина и перекрытие через depth buffer. Оба вида строятся из одной модели. OrbitControls управляет камерой; TransformControls блокирует его во время изменения фигуры. Сцена перестраивается при изменении позы, геометрия и материалы освобождаются.
- `src/main.ts`: русский интерфейс, выбор, преобразование мировых координат в локальные, история, клавиатура и связывание редактора с моделью.
- `src/storage.ts`: проверка JSON, загрузки, автосохранение. Секреты и сервер не нужны.
- `src/style.css`: адаптивная мастерская с боковыми панелями; на телефоне инспектор расположен под сценой.

Координаты правосторонние, Y вверх. Цели конечностей относительно фигуры. Повороты — Euler XYZ в градусах, root преобразует всю фигуру. Таз и грудная клетка образуют последовательность вращений; голова наследует грудную клетку. Нога состоит из двух сегментов по 1.75 единицы; рука — 1.3 и 1.15. Пропорции ориентировочные, а не медицинский стандарт.

## Формат и развитие

JSON содержит `version`, root/rotation/pelvis/chest/head, limits и четыре limb с target/pole/rotation. Камера, режим отображения и история не входят в формат позы. Будущая версия формата может включать идентификатор пропорций и опоры. Редактор пропорций и одежда сознательно отсутствуют; нерабочих кнопок для них нет.

Для развития стоит отделить биндинги DOM и историю из main.ts, добавить выбор отдельных костей для FK и более подробные суставные конусы. Предметы опоры могут быть отдельными объектами сцены с независимым состоянием.
